# crazyAgent development contract

## Change one observable milestone at a time

Define the smallest user-visible behavior that can be checked independently, take a real-run baseline, change one main thing, then rerun the same scenario from the same initial state. Compare success, partial completion, and collateral edits; wall time, model steps, and tool calls; failed calls, retries, and wrong-target actions (even if repaired); and tokens when relevant.

Keep the model and reasoning effort fixed for comparisons. Acceptance uses **medium effort**, which is also the default; do not compare with older off/low runs. A recovered mistake is still reliability evidence.

## Independent checks decide

Logs, screenshots, model reasoning, `turn.ok:true`, `changed:true`, DOM mutations, trusted input, pixel differences, and the agent saying "done" are diagnostics, not proof. Inspect the resulting browser or document state independently of the tool result and final answer. With no checker, ask the user for a verdict: correct, partial, wrong, or blocked. Use console probes only for a specific diagnostic or ground-truth question.

## Regression gates

Use the cheapest gate that can detect the change, then the next:

1. `npm test` for contracts, validation, serialization, and state handling.
2. Real-extension fixture suites for executor changes (`scripts/edge-*-e2e.mjs`). They inspect page state directly but do not evaluate model decisions.
3. A complete real-sidebar scenario for behavior changes, from a known initial state with independent final-state inspection. `scripts/model-eval.mjs` runs scripted real-model scenarios on an isolated profile with independent checkers.

Panel UI changes also run `scripts/ui-preview.mjs --scenario <name>` (mock bridge). Never present unit tests, mock-bridge previews, or direct-executor suites as real-model acceptance. Repeat important model-driven scenarios enough to tell a lucky run from reliability.

## Current focus: Google Docs and semantic editing

Use Docs as a stress test for transferable primitives: exact text targeting, selection, canvas input, layout, menus, and verification. Prefer stable semantic operations for repeated dependent workflows without weakening the general browser tools. Keep stale-view, ambiguity, wrong-target, scoped-recovery, native-dialog, and verification safeguards; if a UI transition invalidates coordinates, avoid coordinates or keep explicit operation state rather than relaxing guards.

Priorities: (1) exact deletion/replacement preserving formatting and neighbors; (2) formatting an exact unique or explicitly ordinal range; (3) compound document creation and formatting in a fresh disposable document; (4) authenticated semantic-table acceptance with collateral-cell and persistence checks. Duplicate text needs an explicit ordinal; never alter an arbitrary occurrence.

## Invariants to keep

- **Tools:** 34 standing model-facing tools (25 general, 8 guarded Docs, `agent_request_help`); `/marathon` (unlisted legacy alias `/plan`) adds `browser_plan` for every turn that starts while the companion-owned marathon switch is on, and the companion's opt-in `confirmIrreversible` setting adds `agent_request_confirmation` for its turns only (both conditionals can coexist). A legacy one-shot `planMode:true` message still works: it turns the shared switch on with the sender's origin, then arms the turn. Marathon M1 (rename + shared switch), M2 (plan carry-over + refill limits), and M3 (deterministic watch ledger + alerts) are landed; the model judge (M4), the phone UI (M5), and the release docs (M6) are in progress per `MARATHON-PLAN.md`. In M2 a turn that ends with open plan items carries the list into the next turn (`seedPlanState`, fail-closed `plan.seed.rejected` fallback); completion nudges and stale reminders refill per accepted revision (2 per stretch) under a 12-per-turn lifetime cap; a seeded-but-untouched turn (no `browser_plan` call, zero tool results) answers `not-assessed` without nudges — that rule still needs its real-model check before it is trusted. Mutations run exclusively in model order; only `browser_tabs`, `browser_places`, `browser_read_text`, `browser_docs_read`, and `browser_downloads` are parallel-safe.
- **Fail closed:** ambiguity, stale or drifted views, unsupported frames, paths outside Downloads, and unavailable colors fail with a code instead of guessing or substituting. ctrl/cmd+W is rejected in code.
- **Refusals stay refusals:** a pre-input `STALE_VIEW`/`AMBIGUOUS_VIEW`/`NO_VIEW` refusal of `click_at`/`select`/`drag` returns `attempted:false` with a fresh full view (text starts `refused <CODE>:`, counted as a failed call), and the same coordinates stay refused until re-measured on a newer view. A drag or selection on an iframe/canvas/video surface reports `unknown`, never a measured no-op. After two consecutive `SIDE_PANEL_CLOSED` results, browser calls fail at once until one succeeds or a new turn starts.
- **Dead model steps are retried in the same turn, never in a new one:** a step whose tool call arrived as DSML text (or, before any tool call, an empty step) gets at most two `agent.steer` notices in a row; a `followup` would start a new turn without the turn's conditional tools. An output-token (max-tokens) cutoff is continued the same way — one `agent.steer` per stopping event, keeping the turn's conditional tools armed. Internal notices use visible source kinds (`agent-notice`, `token-limit-continuation`), never `runtime-context` (the DSH loop replaces that kind with its context snapshot, so the text would never reach the model), and claiming one never resets the turn's repeat guard, executor circuit, no-progress count, or prompt tracking. A reply the runtime rejects as `MALFORMED_RESPONSE` before any action is rerun once by the companion with the turn's modes re-armed. A turn that still did nothing ends as an error or a `BLOCKED:` answer, never as a blank success or raw markup.
- **Evidence is separate from outcome:** results keep `observed`, `expectation`, `outcome`, and `mutationPossible` apart. A failed expectation never triggers re-aiming, retry, or re-mutation. DOM readback is not server persistence. Model-reported `DONE`/`PARTIAL`/`BLOCKED` labels, completed plan items, and `docsVerification` are not verification. URL-sensitive batch expectations (`export_contains`, `toolbar_style`) after a potentially document-changing step are rejected before side effects; page-scoped `text_landed` (a click) is allowed there and reports unknown on scope-mismatch — never a false verdict, no re-mutation. This relaxes evidence validity only; each step's stale-view/ambiguity/wrong-target mutation guards still apply.
- **DSH deep-freezes committed session events:** never annotate `turn/end`. Help, confirmation requests, plan outcomes, and Docs verification travel as bridge activities (`help-request`, `confirm-request`, `turn-outcome`) accepted only for the active turn and session.
- **Confirmation is opt-in and model-reported:** with `confirmIrreversible` off, behavior is exactly as before. With it on, the model is told to ask before irreversible actions and the chat waits for an Approve/Deny that the companion writes as the next turn's `<user_confirmation>` block; the model-reported tool is the primary mechanism, and an executor backstop covers a turn that skips it: in a turn with the setting on that did not start from the user's Approve, the companion stamps `click`/`click_role`/`batch`/`type` commands and the executor refuses, before input, a control whose name matches the reviewed list in `CONFIRM_GUARD_PATTERN` (or a native submit control of a POST form, or `submit:true`) with `CONFIRMATION_REQUIRED`. Enter-key submits and coordinate clicks are not covered. A confirmation wait is not verification that the action was safe.
- **One runner, one turn slot:** chat, new, stop, resume, steer, and snapshots go through `companion/session-controller.mjs`, shared by the panel and the remote API. The marathon switch is the same: one companion-owned state (`companion/marathon.mjs`), changed only through `SessionController.setMarathon`, published as `marathon.state`; clients render it and never assume or optimistically flip it. It resets to off on `/new`, a real chat switch, and companion restart (fail-safe).
- **The watcher only reports (M3 landed; M4 judge pending):** `companion/watch-ledger.mjs` (pure) records every turn — marathon or not — so a mid-turn toggle has history; `assess()` (pure) applies the §3.3.2 signal table; `companion/watcher.mjs` ticks every 20 s on a marathon turn and alerts on hard signals (SILENT_STALL/TOOL_HANG/EXECUTOR_DOWN) without the model. It NEVER steers, stops, sends a bridge command, captures, changes `ok`/`label`/`plan`/`docsVerification`, or triggers a retry. One open alert; kind-change or 15-min re-alert; ≤3 alerts and ≤3 pushes per turn; recovery (3 successful results incl. one mutation, or a plan revision) clears it; "It's fine" snoozes the kind 15 min; an unfinished/blocked/dead/error marathon ending emits `ended-incomplete`. Alerts travel as `chat.watch`/`remote.watch`; the per-turn `watch {checks, alerts, usage}` summary is additive on `chat.done`/`chat.stopped`. Timers are injected for tests and `.unref()`'d in production. The model-based judge (M4) is not wired yet.
- **Automatic updates fail closed:** `companion/updater.mjs` moves only a clean checkout of the official repository that sits exactly on the running version's release tag, only to a newer published non-pre-release, only while no turn runs, marathon is off, and about ten idle minutes have passed, and only under a supervisor (`CRAZYAGENT_SUPERVISED=1`: `npm run dev`, the service). It never forces a checkout, resets, cleans, or touches `.dsh-home` state other than `update-state.json`; a failed install restores the previous tag. Exit code 75 means "restart me". The extension reloads itself only when its on-disk manifest is newer, seen twice 20 s apart, nothing is executing, and at most once per version (`extension/self-update.js`). A development checkout on a branch is never updated.
- **Remote API** (`--remote`, `127.0.0.1:17873`, tailnet-only Serve, its own `0600` token) can never claim `ui`/`tools`, send browser commands, configure the LLM, or read arbitrary files. Port `17872` is the e2e fixture server.
- **One executor at a time:** the side panel or the background service worker, handed over explicitly. System-clipboard work needs the panel.
- **What people see:** no hitboxes on the page (they are drawn only into the model's copy of a capture; people get the clean `displayImage`), and one yellow agent cursor that fades out for every capture.
- **Android:** the reducer must match frames recorded from the real `RemoteHub` (`npm test` fails when stale). Toolchain under `~/Android`. Firebase is configured on this computer (`pushConfigured: true`, a `validate_only` send returned 200), but no push has been delivered. The phone stays paired with `conan-evo-x3`, the designated push sender (2026-11-16 decision): that computer needs the same service-account key and a companion restart before the app can register. Do not re-pair the phone to this computer.
- **Prompt budget:** model guidance stays under the test-enforced 17,100-character ceiling.

## Repository safety

- Do not fork DSH core or hand-edit generated `.dsh-home/browser-agent/llm.patch.yml`.
- Do not run live-model acceptance in unit tests; use fake bridges or isolated browser profiles. Keep test credentials and user data isolated.
- Never kill browsers by executable path. Stop only PIDs/PGIDs you started, scoped to the test profile.
- Reload the unpacked extension and reopen its panel after `extension/` changes. Restart the companion after companion, provider, or config changes.
- When changing documented behavior, update this file, `docs/STATUS.md`, or the relevant project doc in the same change.
