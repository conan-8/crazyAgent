# crazyAgent development contract

## Change one observable milestone at a time

Define the smallest user-visible behavior that can be checked independently, take a real-run baseline, change one main thing, then rerun the same scenario from the same initial state. Compare success, partial completion, and collateral edits; wall time, model steps, and tool calls; failed calls, retries, and wrong-target actions (even if repaired); and tokens when relevant.

Keep the model and reasoning effort fixed for comparisons. Acceptance uses **medium effort**; do not compare with older off/low runs. New configurations default to **Auto**: low for `act`/`navigate`/`rapid`, medium for `inspect`/`synthesize`, using the raw user prompt supplied through `turn.context`; saved choices apply unless an explicit process CLI/env effort override is supplied. A recovered mistake is still reliability evidence.

## Independent checks decide

Logs, screenshots, model reasoning, `turn.ok:true`, `changed:true`, DOM mutations, trusted input, pixel differences, and the agent saying "done" are diagnostics, not proof. Inspect the resulting browser or document state independently of the tool result and final answer. With no checker, ask the user for a verdict: correct, partial, wrong, or blocked. Use console probes only for a specific diagnostic or ground-truth question.

## Regression gates

Use the cheapest gate that can detect the change, then the next:

1. `npm test` for contracts, validation, serialization, and state handling.
2. Real-extension fixture suites for executor changes (`scripts/edge-*-e2e.mjs`). They inspect page state directly but do not evaluate model decisions.
3. A complete real-sidebar scenario for behavior changes, from a known initial state with independent final-state inspection. `scripts/model-eval.mjs` runs scripted real-model scenarios on an isolated profile with independent checkers.

Panel UI changes also run `scripts/ui-preview.mjs --scenario <name>` (mock bridge). Never present unit tests, mock-bridge previews, or direct-executor suites as real-model acceptance. Repeat important model-driven scenarios enough to tell a lucky run from reliability.

## Current focus: Google Docs and semantic editing

Use Docs as a stress test for transferable primitives: exact text targeting, selection, canvas input, layout, menus, and verification. Prefer stable semantic operations for repeated dependent workflows without weakening the general browser tools. Keep stale-view, ambiguity, wrong-target, scoped-recovery, native-dialog, and verification safeguards; if a UI transition invalidates coordinates, avoid coordinates or keep explicit operation state rather than relaxing guards.

Priorities: (1) exact deletion/replacement preserving formatting and neighbors; (2) formatting an exact unique or explicitly ordinal range; (3) compound document creation and formatting in a fresh disposable document; (4) authenticated semantic-table acceptance with collateral-cell and persistence checks. Duplicate text needs an explicit ordinal; never alter an arbitrary occurrence.

- **Editable/chat & image targeting:** visible editable roots (`contenteditable`, ARIA textbox/searchbox) and standalone large content `<img>` elements (≥80×80 CSS px, ≥48×48 natural px, not inside an already-labelled control, capped at 10) receive bounded labels; nested editable descendants and page-dominating editable surfaces stay excluded. `labelText()` reads `.value` only on form controls (`input`/`textarea`/`select`, never `<li>` whose default `HTMLLIElement.value` is `0`), falls back to slotted Shadow DOM text and child `<img alt>`. `labelPage`, `clickLabelled`, and `roleClickProbe` pierce open Shadow DOM `<slot>` projections and Chromium retargeted `elementsFromPoint` hits (handling Web Component buttons like `<sl-button>` inside `<sl-dialog>`, deduplicating shadow host/button pairs, and separating flex/non-inline menuitem spans like `"Page elements Updated ►"` without splitting inline word formatting). `labelPage()` tags controls inside active overlays (`[role="menu|listbox|dialog|alertdialog"]`, `dialog[open]`, `[aria-modal="true"]`, `.goog-menu`, `.docs-bubble*`, excluding `[role="menubar|toolbar"]`) with `popup:true`; `selectListedLabels` (`packages/dsh-browser-extension/lib/view-labels.js`, shared by `formatView` and `formatViewText`) keeps the 60-label cap while prioritizing overflow overlay labels (preserving DOM order) and `formatLabelsHint` boosts them on stale-label errors. Normal viewport `snapshot()` captures pixels **before** `labelAllFrames()` (preventing pre-capture detached popup hitboxes over newer screenshots); `waitForPaint()` settles active combobox/listbox/menu mutations briefly (80 ms quiet, 300 ms idle / 480 ms hard cap; unchanged 2-rAF wait on ordinary pages) and `clickLabelled()` debounces popup option/menuitem dismissal inside its 150 ms ceiling. Coordinate clicks report bounded pre-input hit identity and post-click focus as diagnostics only, never verification or a retry/re-aim trigger. `browser_clipboard` supports copying page images (`source:"image"`, by `label` or solo image tab, fetched via extension `<all_urls>` and normalized to PNG) and Downloads raster images (`source:"download"`, `filename`, magic-byte verified inside the Downloads boundary). Virtual image paste uses host OS-clipboard staging (`packages/dsh-browser-extension/lib/os-clipboard.js`: Wayland `wl-copy`/`wl-paste`, X11 `xclip`, macOS `osascript`, Windows PowerShell) with best-effort preserve/restore + one trusted `Ctrl+V` whenever the side panel is unfocused, falling back to side-panel `navigator.clipboard` and then synthetic paste/drop File delivery. Synthetic image paste suppresses the drop fallback only when scoped image insertion is observed, and reports target/placement uncertainty rather than claiming success.
- **Refusals stay refusals:** a pre-input `STALE_VIEW`/`AMBIGUOUS_VIEW`/`NO_VIEW` refusal of `click_at`/`select`/`drag` returns `attempted:false` with a fresh full view (text starts `refused <CODE>:`, counted as a failed call), and the same coordinates stay refused until re-measured on a newer view. A drag or selection on an iframe/canvas/video surface reports `unknown`, never a measured no-op. A drag revalidates both endpoints exactly before hover and before the press; before the drop the held source only has to stay attached (pointer-follow widgets move it under the cursor), and the destination must be unmoved and the first element at the drop point except for the dragged item (the pressed element, an ancestor that moved with it, or a same-text clone of either); any other cover, a moved destination, or a detached source cancels with `DRAG_STALE_TARGET`. After two consecutive `SIDE_PANEL_CLOSED` results, browser calls fail at once until one succeeds or a new turn starts.
- **Dead model steps are retried in the same turn, never in a new one:** a step whose tool call arrived as DSML text (or, before any tool call, an empty step) gets at most two `agent.steer` notices in a row; a `followup` would start a new turn without the turn's conditional tools. An output-token (max-tokens) cutoff is continued the same way — one `agent.steer` per stopping event, keeping the turn's conditional tools armed. Internal notices use visible source kinds (`agent-notice`, `token-limit-continuation`), never `runtime-context` (the DSH loop replaces that kind with its context snapshot, so the text would never reach the model), and claiming one never resets the turn's repeat guard, executor circuit, no-progress count, or prompt tracking. A turn the runtime ends on `MALFORMED_RESPONSE`, `TRANSPORT` (after the provider's own retries), or `MODEL_SWITCH_COMPACTION_FAILED` before any action is rerun once by the companion with the turn's modes re-armed: a model-switch failure happens before the runtime commits the prompt, so the prompt itself is resent (unless a `user/message` was seen); otherwise a continue notice is sent. Request failures read "The model request failed (CODE)", not "the model's reply could not be used". A turn that still did nothing ends as an error or a `BLOCKED:` answer, never as a blank success or raw markup.
- **Evidence is separate from outcome:** results keep `observed`, `expectation`, `outcome`, and `mutationPossible` apart. A failed expectation never triggers re-aiming, retry, or re-mutation. DOM readback is not server persistence. Model-reported `DONE`/`PARTIAL`/`BLOCKED` labels, completed plan items, and `docsVerification` are not verification. URL-sensitive batch expectations (`export_contains`, `toolbar_style`) after a potentially document-changing step are rejected before side effects; page-scoped `text_landed` (a click) is allowed there and reports unknown on scope-mismatch — never a false verdict, no re-mutation. This relaxes evidence validity only; each step's stale-view/ambiguity/wrong-target mutation guards still apply.
- **Docs semantic fidelity:** HTML export parsing decodes HTML5 named entities (including `&ndash;`, `&mdash;`, `&middot;`, quotes, math, Greek, and Latin-1, with a browser `<textarea>` fallback), honors exact `text-decoration` declarations and ancestor underline/strike-through, not `text-decoration-skip-ink` or a child's `none`. Model-facing `browser_docs_read(format:"html")` summarizes inline `data:image/...;base64,...` attribute payloads (`[omitted N chars]`) while keeping `<img>` tags/attributes and internal `docsExport` callers untouched so embedded images/equations do not truncate the 100k final check, and notes when `#cmnt` anchors appear that Docs omits resolved comments and lists replies as sequential footnotes on the same anchor. Google may flatten checklists to bullets plus line-through: checklist writes require live checklist-control evidence at start and completion plus exported checked-state styling; never infer checklist identity from bullets alone. Font additions accept exact `Remove <font>` evidence when row checked state is unavailable, still require final toolbar verification, and close the modal on failure. The font menu scrolls inside itself, so the lookup reveals one unique exact row below its fold before falling back to More fonts (never choosing between duplicates or returning a point the hit test cannot see); the Fonts dialog keeps showing its unfiltered list for a moment after the search changes, so a row is clicked only once the results are visibly filtered for the query (every row contains it, or "No fonts found.") and the row is hit-reachable. Visible native table grids create and fill cells without the system clipboard (the status is columns × rows); larger grids retain clipboard-preserving paste and fall back to host OS-clipboard HTML staging (`os-clipboard.js` `stageHtml`, with preserve/restore) when the side panel is unfocused. `docsMenuCommand` falls back to `Format → Table ►` when `Alt+/` search times out without finding the command (never when the item is present and disabled). Responsive formatting uses baseline export only for uniform bold/italic/underline selections after an exact control-not-found, with final export verification; ambiguous states still fail closed. Below about 1300 CSS px (a docked side panel leaves ~1160) Docs moves the list buttons into an overflow that its More button opens; Docs marks that button `aria-disabled` although clicking it works, so the toolbar probe refuses only a natively disabled More, and every overflow reveal is followed by refocusing the document (the click otherwise sends later keystrokes to the toolbar). `write-position` polls Drive export briefly while unchanged after `Ctrl+End` + `Enter`, failing closed immediately on any unexpected prefix diff. Write verification fills a span's missing font, size, or color from the export's element rules (`p{}`, `li{}`, `h1{}`–`h6{}`), never over an explicit value, and a failure names the first differing run and attribute. Format verification and preserved-prefix checks (`docsWriteVerify`, `docsTableCreateVerification`) compare the same inherited-normalized rendered values for targets and collateral, and parsed runs inherit weight and italics from `h1{}`–`h6{}` (the `marked` outline keeps explicit marks only). A write block's unset attributes take its own named style's look from the export (`.title`/`.subtitle` over `p{}`, `h1{}`–`h6{}`), never Normal text's; applying a style restarts the write's caret color cache at that style's color. Find and Find-and-replace counters are trusted only once settled, and a reading equal to the previous query's counter must outlast Docs' recount before it counts as uniqueness, a replacement baseline, or replacement proof; `verify-replacement` checks document-tab switches immediately (naming old/new `?tab=`) and failed replacements dismiss the Find & Replace dialog cleanly.
- **Lifetime agent-token usage:** `companion/lifetime-usage.mjs` atomically persists aggregate finalized token-bearing turns (panel and remote; done, stopped, and error) to `.dsh-home/browser-agent/usage.json`, deduping recent turn IDs. `chat.hello.lifetimeUsage` restores the Settings meter and `usage.updated` refreshes it. Release updates preserve this file, while an explicit full clean deletes it. Tracking starts with the first turn recorded by this feature rather than reconstructing history from pruned logs.
- **DSH deep-freezes committed session events:** never annotate `turn/end`. Help, confirmation requests, plan outcomes, and Docs verification travel as bridge activities (`help-request`, `confirm-request`, `turn-outcome`) accepted only for the active turn and session.
- **Confirmation is opt-in and model-reported:** with `confirmIrreversible` off, behavior is exactly as before. With it on, the model is told to ask before irreversible actions and the chat waits for an Approve/Deny that the companion writes as the next turn's `<user_confirmation>` block; the model-reported tool is the primary mechanism, and an executor backstop covers a turn that skips it: in a turn with the setting on that did not start from the user's Approve, the companion stamps `click`/`click_role`/`batch`/`type` commands and the executor refuses, before input, a control whose name matches the reviewed list in `CONFIRM_GUARD_PATTERN` (or a native submit control of a POST form, or `submit:true`) with `CONFIRMATION_REQUIRED`. Enter-key submits and coordinate clicks are not covered. A confirmation wait is not verification that the action was safe.
- **One runner, one turn slot:** chat, new, stop, resume, steer, and snapshots go through `companion/session-controller.mjs`, shared by the panel and the remote API. The marathon switch is the same: one companion-owned state (`companion/marathon.mjs`), changed only through `SessionController.setMarathon`, published as `marathon.state`; clients render it and never assume or optimistically flip it. It resets to off on `/new`, a real chat switch, and companion restart (fail-safe).
- **Proactive watcher with bounded advisory steering (M3/M4/V1–V5 + W1–W4):** `companion/watch-ledger.mjs` (pure) records every turn — normal or marathon; `assess()` (pure) applies the signal table (`SILENT_STALL` suspect 90 s / hard 180 s, `TOOL_HANG` suspect 90 s / hard 180 s, `EXECUTOR_DOWN` 30 s / 120 s, `FAIL_STREAK`, `REPEAT_LOOP`, `SAME_ERROR`, `OBSERVE_ONLY`, `NO_EFFECT`, `PLAN_STALLED` 25 results or 180 s, page-scoped `REVISIT_HINT`, and `SUBGOAL_DWELL` ≥150 s + ≥5 calls + active friction on the same page/subgoal). **V3 page identity (§3.4):** the `REVISIT_HINT` mutation-revisit branch is **page-scoped** (same page + same control + same outcome, threshold 2; unknown page excluded); the judge digest carries bare `mutationRevisits` + compact `subgoalDwell`. **V2 progress accounting (§3.3):** observe / control (`browser_plan`/`agent_request_help`/`agent_request_confirmation`) / act tool classes; `NO VISIBLE CHANGE` ok acts are no-effect (`noProgressResultText`); recovery requires ≥2 effectful act results AND alert signals absent 2 consecutive ticks, OR a higher plan completed count. `companion/watcher.mjs` ticks every 20 s on **every running turn** (normal and marathon; `ended-incomplete` stays marathon-only) and alerts on hard signals without the model. The judge (`companion/watch-judge.mjs`) is ONE stateless tool-less chat-completions call per check through injected getters over the companion's existing key/baseUrl/model (key only in Authorization header, never logged). **V5 routing pin + V5.1 token budget:** `provider:{order:['morph'],allow_fallbacks:false,require_parameters:true}` + `seed:42` only for `deepseek/deepseek-v4.1-flash-1017` on `openrouter.ai` (`judgeRoutingPinned`); other models/URLs send the unpinned request. Judge effort stays **low** and `max_tokens` is **1200** (eliminating large-digest `LENGTH` cutoffs while keeping low effort). **V4 continuation context:** accepted plan seeds emit one seeded plan activity at turn start; internal carry chain (≤3 ancestor prompts, clip 500, never published/agent-prompted) feeds `carriedFrom` + `plan.seededRevision`. **W2 cadence & smart suspect gating:** first call 2 min, routine 3 min ±15% jitter, calm 5 min after 2× `progressing`, alert 2 min otherwise; `suspect` brings a call forward (≥90 s floor) only on the first check, after a non-`progressing` verdict, or when a new suspect signal kind appears (preventing healthy-run budget burn); budget 40 calls / 150k input tokens per turn (budget notice held while an alert is open); 429/timeout doubles next interval once; two-strike rule (`stuck`/`blocked` confidence ≥0.6 with deterministic corroboration or prior non-`progressing` verdict). **W3 bounded advisory steering:** the watcher still has zero browser tools and NEVER clicks, navigates, stops, captures, changes `ok`/`label`/`plan`/`docsVerification`, or bypasses `confirmIrreversible`/`confirmGuard`. When `watchAutoSteer` is enabled (companion setting, default `true`, toggleable in Settings), on a corroborated non-hard `stuck`/`blocked` verdict (confidence ≥0.65, not snoozed, max **2 steers/turn**, **3-min cooldown**), the companion sends `watch.steer` over the `tools` socket and `packages/dsh-browser-extension/lib/watch-steer.js` delivers a sanitized `<watcher_advisory>` notice via **`agent.inject()`** (`target: "next-step"`, `wakeup: false`, `source.kind: 'agent-notice'`) strictly when `turnId` matches the active turn and `agent.status === 'running'`. `sanitizeWatchSteer` strips control chars, rejects URLs and prompt-override phrases, and forces `login`/`captcha`/`permission` blockers to advise `agent_request_help`. Every steer is surfaced transparently on `chat.watch`/`remote.watch` (`steer: {id, text}`) in the pinned sidebar Watch Card (`#watch-card`), turn-root `.watch-row` (outside collapsible `.step-body`), `chat.hello.watch.open` reconnect sync, and phone Watch Card. Per-turn `watch {checks, alerts, usage}` is additive on `chat.done`/`chat.stopped`; timers are injected for tests and `.unref()`'d in production.
- **A watcher verdict is a diagnostic, not verification.** "Progressing" does not mean the work is correct; "stuck" does not mean it failed. The judge explicitly checks process smoothness/headway only, never factual correctness; acceptance still uses independent checkers. V5 pinned routing closed v1's temp-0 instability (gated stuck caught 1.000 / stability 1.000 on tune and holdout, k=5); W2/W3 kept `max_tokens: 1200` (closing V5.1) + smart suspect gating (closing the 35–45 min healthy budget burn) with 0% gated false alerts and 100% stability on tune and holdout replays.
- **Hard stalls do not depend on the model.** Silence, a hung tool, and a lost executor alert deterministically, including when the judge is unavailable, over budget, or returns `unknown`. The judge can never veto a hard signal, and auto-steer never fires on hard stalls.
- **Watcher input is untrusted.** Digest content (tool results, page text, the plan) can never widen what the watcher does beyond bounded text-only `<watcher_advisory>` injection: the judge has no tools, output is schema-validated (`validateVerdict` → `unknown` on core deviation; `sanitizeWatchSteer` drops URLs/override phrases and forces wall blockers to help escalation), reasons and steer notes render as plain text, and `confirmGuard`/user goals are never overridden.
- **Watcher cost is reported separately** from agent usage: the per-turn `watch.usage` counts judge tokens, and judge calls plus input/output/reasoning/cacheRead tokens are logged apart (`watch.judge.*`).
- **Automatic updates fail closed:** `companion/updater.mjs` moves only a clean checkout of the official repository that sits exactly on the running version's release tag, only to a newer published non-pre-release, only while no turn runs, marathon is off, and about ten idle minutes have passed, and only under a supervisor (`CRAZYAGENT_SUPERVISED=1`: `npm run dev`, the service). It never forces a checkout, resets, cleans, or touches `.dsh-home` state other than `update-state.json`; a failed install restores the previous tag. Exit code 75 means "restart me". The extension reloads itself only when its on-disk manifest is newer, seen twice 20 s apart, nothing is executing, and at most once per version (`extension/self-update.js`). A development checkout on a branch is never updated. The sidebar receives authoritative state through `chat.hello` and `update.state`; pending/installing/failure notices are informational and dismissible, never an approval requirement, and a completed update is announced once after restart. Settings can request an immediate check and install an already-fetched pending release, but the same eligibility, supervisor, idle-turn, and Marathon-off guards still apply.
- **Remote API** (`--remote`, `127.0.0.1:17873`, tailnet-only Serve, its own `0600` token) can never claim `ui`/`tools`, send browser commands, configure the LLM, or read arbitrary files. Port `17872` is the e2e fixture server.
- **One executor at a time:** the side panel or the background service worker, handed over explicitly. System-clipboard work needs the panel. A panel closed mid-turn leaves its debugger session attached; the next executor detaches a session of its own extension (Chrome lets only the attaching extension detach) and re-attaches once, and only a foreign debugger stays `DEBUGGER_BUSY` ("DevTools or another extension"). A panel that connects mid-turn shows the running turn (`chat.hello.turn`, status `thinking`) instead of sending `chat.new`. `browser_navigate` from a browser page (`edge://`, `chrome://`, extension pages; not `about:`) opens the destination in a new tab and leaves the browser page as it was: Edge kept refusing trusted input on a tab navigated in place away from its new-tab page. `browser_upload` finds the assigned input by its token, not its position; a page that swaps in a fresh input after the change event carried exactly the file (Gmail compose) reports `inputReplacedByPage` change-event evidence, which is not proof the page kept the file.
- **What people see:** no hitboxes on the page (they are drawn only into the model's copy of a capture; people get the clean `displayImage`), and one yellow agent cursor that fades out for every capture.

## Repository safety

- Do not fork DSH core or hand-edit generated `.dsh-home/browser-agent/llm.patch.yml`.
- Do not run live-model acceptance in unit tests; use fake bridges or isolated browser profiles. Keep test credentials and user data isolated.
- Never kill browsers by executable path. Stop only PIDs/PGIDs you started, scoped to the test profile.
- Reload the unpacked extension and reopen its panel after `extension/` changes. Restart the companion after companion, provider, or config changes.
- When changing documented behavior, update this file, `docs/STATUS.md`, or the relevant project doc in the same change.
