# Firefox port audit — Firefox-only vs Chromium-only, verified 2026-11-03

Version baseline: Firefox stable **159.0.1** (2026-10-27), ESR **153.6.0esr**, Beta 160, Nightly 161 ([product-details](https://product-details.mozilla.org/1.0/firefox_versions.json)). MDN browser-compat-data **8.1.8, published 2026-11-02** was queried directly for every "Chrome: false" claim below.

### Panel-window caveat (Q11)
`windows.create({type:"panel"|"detached_panel"})` is accepted, but current Firefox routes **all non-`normal` types to a popup window** ("All types other than `normal` create `popup`-type windows", [ext-windows.js](https://github.com/mozilla-firefox/firefox/blob/main/browser/components/extensions/parent/ext-windows.js)), and the in-tree schema still says panel types create a popup unless `--enable-panels` is set ([windows.json](https://github.com/mozilla-firefox/firefox/blob/main/browser/components/extensions/schemas/windows.json)). Practically you get a window without address bar/toolbar, not a true panel. Chrome's `panel` is deprecated and ChromeOS-allowlist only ([Chrome windows](https://developer.chrome.com/docs/extensions/reference/api/windows)).

## Firefox MV2 / MV3 background model (Q14)
- **MV2 is still supported** in 159 and ESR 153. No end-of-life date announced; Mozilla's last explicit public commitment is the Feb 2025 post "Firefox will continue supporting both blockingWebRequest and declarativeNetRequest" and "Support for both Manifest V2 and V3" ([Mozilla blog](https://blog.mozilla.org/en/firefox/firefox-manifest-v3-adblockers/)). AMO's current distribution docs still describe shipping MV2 ([Extension Workshop](https://extensionworkshop.com/documentation/publish/distribute-manifest-versions/)). I could not find any 2026 Mozilla statement changing this.
- **MV3 background = event page, never a service worker** (`background.service_worker` unsupported, bug 1573659); `persistent: true` **errors** in MV3, so no persistent background page in MV3. Use `background.scripts` (or `page`) ([MDN background](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background)).
- **WebSocket keepalive:** event pages suspend after an idle timeout (implemented in [bug 1748525](https://bugzilla.mozilla.org/show_bug.cgi?id=1748525)); MDN notes message ports do **not** prevent shutdown ([MDN background scripts](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Background_scripts)). A WebSocket alone is not a documented keepalive — plan on `alarms` + reconnect, or ship MV2 with `persistent: true`. Undocumented trick: an open `StreamFilter` cancels the idle suspend ([bug 1759300](https://bugzilla.mozilla.org/show_bug.cgi?id=1759300)).

## Uncertain / changed recently
- **`trial.ml` on Release is unverified.** Mozilla's docs say Nightly-by-default and pref-gated elsewhere, but `browser.ml.enable` and `extensions.ml.enabled` both default to `true` in current `all.js`. Treat release availability as "test on your target channel".
- **Containers default state:** MDN says "only enabled by default in Nightly", but `privacy.userContext.enabled` defaults to `true` in `firefox.js`. Doc likely stale; verify on a clean profile.
- **Panel windows:** schema mentions `--enable-panels`, current code maps to popup, and I could not find the flag in current `nsAppRunner.cpp`. Behaviour today is "chrome-less popup", not a true panel.
- **MV2 end date:** none found. Absence of an announcement is not a guarantee.
- **Changed 2025–2026 (may affect your port):** Firefox 137 native tab groups → 138 `tabs.group` → 139 `tabGroups`; 136 vertical tabs/sidebar revamp, 142 `browserSettings.verticalTabs`; 149 `splitViewId`, `action.openPopup()` without gesture; 150 WebAuthn RP ID; 152 injection into `moz-extension://` documents removed; **153 `file://` access became a separate opt-in permission** (breaks silent local-file reads), plus `documentId` everywhere, `userScripts.execute()`, and `publicSuffix` — which Chrome also shipped in 153, so it is **not** Firefox-only.
- **Chrome 148+ supports the `browser.*` namespace** ([Chrome docs banner](https://developer.chrome.com/docs/extensions/reference/api/windows)), so namespace differences are no longer a porting argument.
- Not verified: whether Chrome has any shipped/intended `tabs.hide`; no public signal found.
